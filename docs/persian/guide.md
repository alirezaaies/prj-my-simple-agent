# آموزش عملی ایجنت شخصی

نویسنده: علیرضا خواجه‌وندی. تاریخ بررسی نسخه: ۲۰۲۶-۱۰-۱۴.

## ۱. این نسخه چه چیزی را کامل می‌کند؟

نسخهٔ اول یک برنامهٔ ترمینالی برای استفادهٔ شخصی است: پرسش‌ها را با مدل Ollama پاسخ می‌دهد، نکته‌های صریح حافظه و کارهای شخصی را نگه می‌دارد، برای تحقیق شواهد وب می‌گیرد و فایل‌های کوچک کد و متن را در پوشهٔ انتخابی می‌خواند یا تغییر پیشنهاد می‌دهد. ابزار یعنی یک تابع Python که مدل می‌تواند اجرای آن را درخواست کند. خود مدل فایل را باز نمی‌کند؛ برنامه درخواست را اعتبارسنجی می‌کند، تابع مجاز را اجرا می‌کند و نتیجهٔ واقعی را به مدل برمی‌گرداند.

در کد اولیه تنظیمات، ذخیرهٔ JSON، تعریف ابزار، شبکه، دستورهای مدل و حلقهٔ تعاملی در یک فایل جمع شده بودند. فایل اصلی بیش از هزار خط داشت. نسخهٔ فعلی این مسئولیت‌ها را جدا می‌کند، بدون اضافه کردن چارچوب ایجنت، دیتابیس، embedding یا سرور. برای فهم هر درخواست کافی است چند ماژول کوچک را دنبال کنید.

خطاهای مشخص شروع برنامه شامل نخواندن فایل محیط، متفاوت بودن نام متغیر کلید در کد و تنظیم محلی، و نصب نبودن وابستگی‌ها در Python انتخاب‌شده بود. مشکلات دیگر شامل وابستگی مسیر حافظه به محل اجرای ترمینال، خالی شدن ظاهری داده در صورت JSON خراب، ذخیرهٔ مستقیم روی فایل قبلی، استفادهٔ مجدد از شناسهٔ کار حذف‌شده، رشد بی‌حد تاریخچه، اعتبارسنجی نامنظم ابزار و چاپ متن کامل خطاهای شبکه بود.

نام فعلی متغیر کلید با یک نام جایگزین پشتیبانی می‌شود. فایل‌های شخصی قدیمی حفظ و در پوشهٔ دادهٔ محلی کپی می‌شوند. کدهای آموزشی اولیه در examples/legacy نگه داشته شده‌اند؛ نام‌های قبلی در ریشه حالا نسخهٔ جدید را اجرا می‌کنند. هیچ مقدار کلید یا دادهٔ شخصی در این گزارش و ضمیمهٔ کد قرار نمی‌گیرد.

در این نسخه، تغییر درخواست‌شده توسط مدل باید قابل بررسی باشد: تغییر حافظه و کارها آرگومان را نشان می‌دهد، تغییر فایل تفاوت کد را نشان می‌دهد و فقط با YES اعمال می‌شود. دستور مستقیم افزودن نکته یا کار همان دستور صریح کاربر است و فوری انجام می‌شود؛ حذف همچنان تأیید می‌خواهد. اجرای خودکار دستورهای shell یا تست تولیدشده توسط مدل وجود ندارد.

کد و کتابخانه‌ها اشتراک پولی نمی‌خواهند. cloud از اعتبار حساب Ollama استفاده می‌کند؛ رایگان بودن حساب به معنی اعتبار نامحدود نیست. اجرای محلی مصرف API ابری را حذف می‌کند، اما به سخت‌افزار، دانلود، فضای ذخیره و برق نیاز دارد. مدل cloud تست‌شده gemma4:31b بود. اجرای مدل محلی در این جلسه تست نشده است.

## ۲. نصب و تنظیم قدم‌به‌قدم

از Python نسخهٔ ۳٫۱۱ یا جدیدتر استفاده کنید. PowerShell را در پوشه‌ای باز کنید که run_agent.py داخل آن است. محیط مجازی محل جداگانه‌ای برای کتابخانه‌های همین پروژه است تا بسته‌های پروژه با ابزارهای دیگر سیستم مخلوط نشوند.

```powershell
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

مسیر صریح مفسر مهم است: کتابخانه باید در همان Python نصب شود که برنامه را اجرا می‌کند. فعال‌سازی محیط اجباری نیست. اگر PowerShell اجرای Activate.ps1 را مسدود کرد، همین مسیر صریح را استفاده کنید؛ تغییر سیاست اجرای سیستم لازم نیست. برای دکمهٔ Run در VS Code هم مفسر .venv پروژه را انتخاب کنید.

فقط در نصب تازه‌ای که .env ندارد، نمونه را کپی کنید. این دستور را روی فایل موجود اجرا نکنید، چون تنظیم قبلی را جایگزین می‌کند. کلید را با ویرایشگر داخل فایل محلی وارد کنید؛ آن را چاپ یا اسکرین‌شات نکنید و در گفتگو نفرستید.

```powershell
Copy-Item .env.example .env
```

نام استاندارد کلید OLLAMA_API_KEY است. نام OLLAMA_FREE_API_KEY هم پشتیبانی می‌شود و فایل فعلی شما لازم نیست عوض شود. متغیرهای محیط سیستم نسبت به .env اولویت دارند. اگر هر دو نام کلید موجود باشند، نام استاندارد اولویت دارد. تابع Config.load فایل را با dotenv_values می‌خواند و مقدارها را به محیط پردازش تزریق نمی‌کند. فیلد کلید در نمایش شیء تنظیمات هم چاپ نمی‌شود.

نمونهٔ زیر فقط تنظیم عمومی است و مقدار کلید ندارد:

```text
OLLAMA_MODEL=gemma4:31b
OLLAMA_BASE_URL=https://ollama.com/v1
AGENT_TIMEOUT=60
```

اکنون بررسی محلی و سپس اجرای تعاملی را انجام دهید:

```powershell
.\.venv\Scripts\python.exe run_agent.py --check
.\.venv\Scripts\python.exe run_agent.py
```

بررسی محلی مدل، نشانی سرویس، پوشهٔ کاری، مسیر داده و تعداد رکوردها را نشان می‌دهد. هیچ درخواست Ollama نمی‌فرستد؛ پس فقط آماده بودن تنظیم محلی را ثابت می‌کند. اجرای نخست ممکن است memory.json و tasks.json قدیمی را در data کپی کند. اجرای بعدی دادهٔ جدید را با نسخهٔ قدیمی جایگزین نمی‌کند. شناسهٔ کارهای قبلی حفظ و شمارندهٔ next_id اضافه می‌شود تا شناسهٔ آینده تکرار نشود.

برای کار روی یک پروژهٔ دیگر، پوشهٔ موجود آن را بدهید. ابزار فایل در همان پوشه محدود می‌شود، ولی حافظهٔ شخصی همچنان در data همین پروژهٔ ایجنت است.

```powershell
.\.venv\Scripts\python.exe run_agent.py --workspace 'E:\projects\demo'
```

برای اجرای محلی، Ollama را جداگانه نصب و مدل مناسب توان سیستم انتخاب کنید. نمونهٔ دستورها در ادامه است. اگر برنامهٔ دسکتاپ Ollama سرور را اجرا کرده، همان کافی است؛ در غیر این صورت سرور را در ترمینال جدا اجرا کنید. این‌ها دستور راه‌اندازی هستند؛ در این جلسه مدل محلی دانلود و اجرا نشده است.

```powershell
ollama pull qwen3:8b
ollama serve
```

```text
OLLAMA_BASE_URL=http://localhost:11434/v1
OLLAMA_MODEL=qwen3:8b
```

این مسیر کلید cloud نمی‌خواهد. حتی اگر کلید ابری در .env باقی باشد، مفسر برای سرور محلی فقط مقدار نمایشی ollama می‌فرستد. مدل کوچک ممکن است دستور ابزار را ضعیف‌تر دنبال کند؛ اول گفتگو و یک کار نمونه را امتحان کنید. نشانی‌های مجاز API فقط نشانی دقیق Ollama cloud یا نشانی loopback با مسیر /v1 هستند. نشانی اینترنتی دلخواه پذیرفته نمی‌شود تا کلید به سرویس اشتباه نرود.

## ۳. استفادهٔ روزمره و تمرین آموزشی

برای کار چندمرحله‌ای، درخواست کامل را یک‌بار بدهید. ایجنت برنامهٔ موقت می‌سازد، گام‌ها را اجرا می‌کند و پس از پاسخ خالی یا میانی خودکار ادامه می‌دهد. ذخیرهٔ فایل همچنان تأیید می‌خواهد. بعد از اجرا، /plan آخرین برنامه را نشان می‌دهد. این برنامهٔ موقت با کارهای شخصی دائمی در /task و /tasks متفاوت است.

مثلاً هر سه مسیر myportfolio/index.html و myportfolio/style.css و myportfolio/script.js را در یک درخواست بخواهید. ایجنت هر سه را می‌نویسد، ارجاع‌ها را مرور می‌کند و فقط پس از تکمیل گام‌ها و وجود فایل‌ها پایان می‌دهد. رد تغییر اجرا را متوقف می‌کند و تغییر تأییدشدهٔ قبلی باقی می‌ماند. معنا و کیفیت گام‌ها به مدل وابسته است؛ کد فقط وضعیت گام و وجود و اندازهٔ فایل را بررسی می‌کند، نه طراحی ظاهری یا اجرای برنامه را.

رابط ترمینال انگلیسی است و پاسخ مدل هم به‌صورت پیش‌فرض انگلیسی خواهد بود، حتی اگر درخواست فارسی یا به زبان دیگر نوشته شود. برای تغییر زبان پاسخ، صریحاً بخواهید؛ مثلاً «این موضوع را به فارسی توضیح بده». این انتخاب مشکل نمایش راست‌به‌چپ در ترمینال را کمتر می‌کند و پاسخ چندزبانه همچنان با درخواست شما در دسترس است.

با /help و /status شروع کنید. دستورهای دارای اسلش را خود برنامه اجرا می‌کند. متن معمولی به مدل می‌رود و مدل ممکن است ابزار درخواست کند. بنابراین /task بدون درخواست API کار می‌سازد؛ عبارت «یک کار اضافه کن» اول به مدل می‌رود و سپس درخواست ابزارش نیاز به بررسی دارد.

```text
/help
/status
/remember I prefer practical Python examples
/memory
/update I prefer practical Python examples | I prefer short Python examples
```

متن فارسی هم می‌توانید به‌جای جمله‌های نمونه بنویسید. نکتهٔ حافظه کوتاه، پایدار و مناسب ارسال به سرویس انتخابی باشد. نکتهٔ تکراری با نادیده گرفتن بزرگی حروف اضافه نمی‌شود. اصلاح باید متن قبلی را دقیق، جز فاصلهٔ ابتدا و انتها و بزرگی حروف، مشخص کند؛ جستجوی معنایی انجام نمی‌شود. در دستور OLD | NEW اولین علامت خط عمودی جداکننده است. کلید و رمز را در حافظه ننویسید. مدل فقط با درخواست صریح شما و تأیید تغییر، نکته را ذخیره می‌کند.

```text
/task Read the Python functions tutorial
/tasks
/done 1
/delete-task 1
```

عدد نمونهٔ ۱ را با شناسه‌ای که /tasks نشان می‌دهد عوض کنید. کار تکمیل‌شده با وضعیتش باقی می‌ماند. تکمیل با حذف فرق دارد: تکمیل رکورد را حفظ می‌کند، حذف پس از YES رکورد را برمی‌دارد. پس از حذف بزرگ‌ترین شناسه هم کار جدید شناسهٔ استفاده‌نشده می‌گیرد؛ اشارهٔ قدیمی گفتگو به کار دیگری تبدیل نمی‌شود.

```text
/forget I prefer short Python examples
/forget-all
/reset
/exit
```

دو دستور اول تأیید حذف می‌خواهند. Enter یعنی لغو. Reset فقط تاریخچهٔ داخل پردازش را پاک می‌کند و حافظه و کارهای ذخیره‌شده باقی می‌مانند. Exit برنامه را می‌بندد. نسخهٔ پشتیبان قبلی ممکن است نکتهٔ حذف‌شده را هنوز داشته باشد؛ برای حذف آن کپی محلی هم ابتدا برنامه را ببندید و نسخهٔ پشتیبان را آگاهانه مدیریت کنید. حذف دادهٔ فعال با پاک شدن همهٔ کپی‌های قدیمی یکسان نیست.

برای یک پاسخ سریع از --ask استفاده کنید. در این حالت تغییر درخواست‌شده توسط مدل خودکار رد می‌شود چون بررسی تعاملی ندارد؛ دستور مستقیم غیرحذفی همچنان اجرا می‌شود. هیچ کلید واقعی را در آرگومان فرمان یا متن پرسش نگذارید.

```powershell
.\.venv\Scripts\python.exe run_agent.py --ask 'Explain Python list comprehensions'
.\.venv\Scripts\python.exe run_agent.py --ask '/status'
.\.venv\Scripts\python.exe run_agent.py --no-memory
```

حالت بدون حافظه ابزار نکته و کار را غیرفعال می‌کند و نکته‌های ذخیره‌شده را به مدل نمی‌دهد. تاریخچهٔ موقت همان جلسه تا reset یا خروج باقی می‌ماند. متن کامل گفتگو روی دیسک ذخیره نمی‌شود. حداکثر ده نوبت کامل اخیر با سقف حجم نگه داشته می‌شود؛ نوبت‌های قدیمی کامل کنار گذاشته می‌شوند. تحقیق طولانی را به درخواست‌های مشخص تقسیم کنید.

تمرین پیشنهادی: یک نکته و کار ساختگی اضافه کنید، برنامه را ببندید و دوباره /memory و /tasks را ببینید. ماندن آن‌ها ذخیرهٔ دائمی JSON را نشان می‌دهد. Reset آن‌ها را حذف نمی‌کند. در پایان فقط رکوردهای ساختگی خودتان را با متن یا شناسهٔ دقیق حذف کنید.

## ۴. کدنویسی و تحقیق با منبع

ابزار فایل متن UTF-8 و کد کوچک تا ۶۴ کیلوبایت را می‌پذیرد. مسیر مطلق، رفتن به پوشهٔ والد، خروج از پوشهٔ کاری، اجزای مخفی، فایل‌های حافظه، پوشه‌های وابستگی و نام‌های رایج اطلاعات محرمانه مسدودند. فهرست پروژه حداکثر ۲۰۰ فایل مجاز نشان می‌دهد. متن فایل دادهٔ ورودی است؛ توضیح داخل کد به دستور سیستمی تبدیل نمی‌شود.

ابتدا ابزار مستقیم را امتحان کنید تا بدانید مدل چه چیزی می‌بیند:

```text
/files
/read README.md
```

برای تمرین کدنویسی، در پوشهٔ نمونهٔ جداگانه فایل demo.py را بسازید:

```python
def add(a, b):
    return a - b
```

سپس بنویسید: «فایل demo.py را بخوان. توضیح بده چرا add اشتباه است. کوچک‌ترین اصلاح را پیشنهاد کن و فقط بعد از نشان دادن تفاوت ذخیره کن». دستیار باید read_file را اجرا کند، تفریق را تشخیص دهد و با write_file متن کامل اصلاح‌شده را پیشنهاد دهد. مسیر و تفاوت را بررسی کنید. YES تغییر را ذخیره و Enter لغو می‌کند. ابزار بررسی می‌کند فایل در زمان تأیید شما توسط فرد دیگری تغییر نکرده باشد. ذخیرهٔ موفق یعنی فایل نوشته شده؛ درستی برنامه را ثابت نمی‌کند.

اصلاح کوچک مورد انتظار:

```python
def add(a, b):
    return a + b
```

در همان پوشه‌ای که demo.py قرار دارد، خودتان بررسی واقعی را اجرا کنید. ابزار اجرای کد در ایجنت نیست و نباید ادعا کند این دستور را قبلاً اجرا کرده است:

```powershell
python -c "from demo import add; assert add(2, 3) == 5; print('PASS')"
git diff
```

جایگزینی کامل فایل برای یادگیری ساده است، اما برای فایل کوچک طراحی شده است. تبدیل AST، پچ معنایی، جستجوی مخزن بزرگ، commit خودکار و سامانهٔ rollback وجود ندارد. قبل از commit تفاوت Git را ببینید. این نسخه مخزن پروژهٔ دیگر را از طرف شما ایجاد یا commit نمی‌کند.

تحقیق دو مرحله دارد: سرچ متن کوتاه و URL می‌دهد؛ خواندن صفحه متن HTML را دریافت می‌کند. درخواست خوب هر دو را می‌خواهد و مشخص می‌کند کدام ادعا در متن منبع پشتیبانی می‌شود.

```text
/search Python official tutorial list comprehensions
/open https://docs.python.org/3/tutorial/datastructures.html
```

نمونه: «مستندات رسمی Python دربارهٔ list comprehension را پیدا کن، صفحهٔ مرتبط را بخوان و سه نکته را با URL منبع توضیح بده. اگر جزئیاتی در صفحه نیست، صریح بگو». عنوان و نشانی نتیجهٔ سرچ فقط سرنخ است. متن صفحه ممکن است کوتاه‌شده، قدیمی، ناقص یا اشتباه باشد. نقل‌قول باید عیناً در متن دریافت‌شده وجود داشته باشد؛ در غیر این صورت باید بازگویی باشد.

خوانندهٔ وب فقط HTTPS عمومی روی پورت ۴۴۳ می‌پذیرد، مقصد هر تغییر مسیر را دوباره بررسی می‌کند، نشانی خصوصی یا رزروشده را رد می‌کند و به همان IP بررسی‌شده با کنترل نام میزبان در TLS وصل می‌شود. محتوا بدون فشرده‌سازی درخواست می‌شود، سقف دریافت ۲ مگابایت و سقف متن خروجی ۱۲ هزار نویسه است. ورود به سایت، اجرای JavaScript و خواندن PDF ندارد. صفحهٔ ورود یا محافظت ربات ممکن است شواهد ناقص یا غیرقابل‌دریافت بدهد. شکست سرچ به‌صورت خطا گزارش می‌شود، نه نتیجهٔ ساختگی.

مقابله با دستورهای مخرب دو لایه دارد: پرامپت محتوای وب و فایل و حافظه را نامطمئن معرفی می‌کند؛ کد ابزار نیز مسیر، آرگومان، نشانی سرویس و تأیید تغییر را محدود می‌کند. پرامپت به‌تنهایی تضمین نمی‌کند مدل هیچ‌گاه متن مخرب را دنبال نکند. تغییر و شواهد را همچنان بررسی کنید. مدت DNS به resolver سیستم‌عامل وابسته است؛ بودجهٔ زمان خوانندهٔ وب محدودیت عملی است و تضمین مطلق برای همهٔ عملیات resolver نیست.

## ۵. پیاده‌سازی را بفهمیم و توسعه دهیم

مسیر درخواست چنین است: run_agent.py، سپس cli.main، سپس تنظیمات و ذخیره و ابزار، سپس Agent.ask، سپس Ollama، سپس اعتبارسنجی و اجرای ابزار، نتیجهٔ ابزار و پاسخ نهایی. مدل نام تابع و آرگومان JSON پیشنهاد می‌دهد. Toolbox تصمیم می‌گیرد نام مجاز است، آرگومان‌ها دقیق و دارای نوع درست هستند و تغییر تأیید شده است یا نه. همین اتصال به تابع واقعی، گفتگوی متنی را به ایجنت دارای ابزار تبدیل می‌کند.

تنظیمات در config.py است. dataclass مدل و نشانی، مسیر پروژه و پوشهٔ کاری، timeout، سقف دور ابزار و تاریخچه را یک‌جا نگه می‌دارد. فیلتر راز مقدارهای محرمانهٔ شناخته‌شده را از تنظیمات می‌گیرد و وجودشان را در ورودی و ذخیرهٔ داده رد می‌کند. قالب رایج انتساب کلید و رمز را در خروجی فایل و مدل هم می‌پوشاند. این فیلتر عملی است؛ راز ناشناخته، رمزگذاری‌شده یا تکه‌شده را به‌طور عمومی تشخیص نمی‌دهد.

ذخیره در storage.py است. هر تغییر قفل انحصاری می‌گیرد، JSON فعلی را می‌خواند و اعتبارسنجی می‌کند، روی کپی کار می‌کند، دوباره اعتبارسنجی می‌کند، فایل موقت هم‌پوشه می‌نویسد و پس از flush آن را به‌صورت اتمیک جایگزین می‌کند. وضعیت معتبر قبلی پیش از جایگزینی در .json.bak کپی می‌شود. اگر JSON یا ساختار خراب باشد، تغییر متوقف می‌شود و فایل اصلی باقی می‌ماند. پشتیبان برای بازیابی است؛ دیتابیس تاریخچه یا صندوق رمزگذاری‌شده نیست.

نمونهٔ ساختار کار با دادهٔ ساختگی:

```json
{
  "tasks": [{"id": 1, "title": "Practice Python", "completed": false}],
  "next_id": 2
}
```

تابع Toolbox.add توضیح ابزار، نام آرگومان و نوع JSON، تابع اجرایی و نیاز به تأیید را ثبت می‌کند. schema مدل از همان ثبت ساخته می‌شود تا تعریف ابزار با اجرای آن هماهنگ بماند. فیلد اضافه یا ناشناخته و مقدار بولی به‌جای شناسهٔ عددی رد می‌شود. تأیید پیش‌فرض تغییر را رد می‌کند تا رفتار اجرای یک‌باره و تست روشن باشد.

ProjectFiles فهرست، خواندن، ساخت تفاوت و ذخیرهٔ اتمیک را جدا کرده است. شبکهٔ صفحهٔ وب در web.py است؛ کلاینت گفتگو کلید را فقط به سرویس تنظیم‌شدهٔ مدل می‌فرستد. خواندن وب کلاینت جدا دارد و هدر احراز هویت Ollama را به ارث نمی‌برد. خطای API به‌صورت نوع کوتاه خطا یا کد وضعیت گزارش می‌شود؛ هدر و متن کامل پاسخ خطا چاپ نمی‌شود.

Agent.ask یک نوبت می‌سازد، تاریخچهٔ کامل اخیر و نکتهٔ اختیاری حافظه را می‌گیرد، chat completions را صدا می‌زند و پاسخ مدل را ثبت می‌کند. هر tool_call_id نتیجهٔ متناظر دارد. JSON نامعتبر یا قطع‌شده به خطای قابل اصلاح تبدیل می‌شود. پاسخ خالی و متن پیشرفت میانی، هنگام اجرای برنامه، دستور ادامهٔ خودکار ایجاد می‌کند. پرسش عادی همچنان بدون برنامه پاسخ عادی می‌گیرد.

کار نوشتن فایل با plan_work و complete_step و finish_work انجام می‌شود. کلاس موقت WorkPlan در work.py همهٔ گام‌ها و مسیرها را ثبت می‌کند، اجازهٔ حذف تعهد قبلی را نمی‌دهد و پایان با گام ناتمام یا فایل مفقود و خالی را رد می‌کند. ابزار pause_work مانع واقعی را گزارش می‌دهد. مسیر نوشتن باید در برنامه باشد؛ تأیید کاربر و کنترل مسیر و راز همچنان برقرار است. خلاصهٔ پایان از finish_work موفق می‌آید و در تاریخچه ثبت می‌شود.

پیش‌فرض ۳۰ دور ابزار است و در صورت نیاز یک درخواست نهایی بدون ابزار، توقف به‌علت سقف را روشن گزارش می‌کند. در هر دور حداکثر شش ابزار اجرا می‌شود. سه پاسخ بی‌پیشرفت یا سه خطای یکسان توقف می‌دهد. رد تغییر، عمل‌های بعدی همان بسته را هم لغو می‌کند. تلاش خودکار شبکه در SDK غیرفعال است، چون خطای شبکه پس از نوشتن ممکن است نتیجهٔ نامشخص داشته باشد. خطای API ادعای rollback یا پایان نمی‌کند.

تنظیم عمومی AGENT_MAX_ROUNDS بین ۱ و ۱۰۰ با پیش‌فرض ۳۰ و AGENT_MAX_OUTPUT_TOKENS بین ۲۵۶ و ۳۲۷۶۸ با پیش‌فرض ۸۱۹۲ است. سقف خروجی بزرگ‌تر به آرگومان کامل ابزار CSS و JS کمک می‌کند؛ به معنی تولید همیشگی همان تعداد توکن نیست. سقف بالاتر ممکن است اعتبار بیشتری مصرف کند. کلید واقعی در درخواست یا گزارش لازم نیست.

اگر ابزار موفق شد و درخواست بعدی مدل خطا داد، تغییر همچنان ذخیره شده است. تاریخچه نتیجهٔ تأییدشده را نگه می‌دارد. قبل از تکرار تغییر، /memory یا /tasks یا git diff را بررسی کنید. نبود جملهٔ نهایی مدل به معنی rollback عمل قبلی نیست. قطع شدن هم برای پیام ابزار ناتمام، نتیجهٔ صریح نامشخص می‌گذارد تا بازپخش گفتگو ناقص نباشد.

برای افزودن ابزار، اول تابع محدود و دارای نتیجهٔ روشن بنویسید؛ با Toolbox.add ثبت کنید، اگر تغییر ایجاد می‌کند تأیید را فعال کنید و برای خطاهای واقعی آن آزمون بنویسید. برای ظاهر خودکارتر، ابزار اجرای shell بی‌حد اضافه نکنید. ابزار دارای حساب و کلید و دسترسی گسترده باید محدودهٔ قابل اعمال در کد و جریان دادهٔ روشن داشته باشد.

ضمیمهٔ گزارش کد کامل نگهداری‌شده، آزمون‌ها و اسکریپت‌ها را مستقیم از مخزن می‌خواند. ابتدا توضیح مسئولیت هر بخش را بخوانید و بعد کد همان فایل را دنبال کنید. پس از ویرایش کد و ساخت مجدد گزارش، ضمیمه خودکار تازه می‌شود؛ ویرایش فصل آموزشی جداگانه انجام می‌شود.

## ۶. آزمون و رفع اشکال

آزمون‌های محلی با unittest، پوشهٔ موقت، کلید ساختگی و مدل ساختگی اجرا می‌شوند. کلید واقعی لازم ندارند، دادهٔ شخصی را تغییر نمی‌دهند و درخواست وب ندارند. بعد از تغییر ذخیره، اجرای ابزار، کنترل مسیر یا حلقهٔ مدل، آن‌ها را اجرا کنید:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

مجموعهٔ نهایی ۵۱ آزمون دارد: ۵۰ پاس و یک آزمون ساخت symlink به‌دلیل نبود مجوز ویندوز اجرا نشد. آزمون مسیر resolveشدهٔ ساختگی هم منطق رد خروج از پوشه را بررسی می‌کند. پوشش شامل تنظیمات، فیلتر راز، ساختار و خرابی داده، پشتیبان، قفل، شناسهٔ پایدار کار، لغو تأیید، تغییر هم‌زمان فایل، آرگومان نادرست و خطای API است. آزمون تازه حالت HTML و سپس پاسخ خالی را بازسازی می‌کند، CSS و JS را بدون درخواست دوم می‌سازد، فایل مفقود را در پایان رد می‌کند و خروجی قطع‌شده و توقف بی‌پیشرفت را بررسی می‌کند.

تست واقعی جداگانه مقدار کمی اعتبار API مصرف می‌کند. پوشهٔ خالی موقت و دادهٔ ساختگی دارد و تأیید خودکار فقط در همان محیط تست انجام می‌شود. گفتگو، رفت‌وبرگشت ابزار ساخت کار و خواندن و اصلاح تابع نمونه را بررسی می‌کند. نکته‌ها و کارها و کد پروژهٔ شخصی شما به مدل فرستاده نمی‌شود.

```powershell
.\.venv\Scripts\python.exe scripts\smoke_test.py --live
```

در تاریخ ۲۰۲۶-۱۰-۱۴ هر سه سناریوی cloud پاس شدند. تست واقعی جداگانهٔ دریافت صفحهٔ عمومی و سرچ نیز URL شواهد برگرداند. این نتیجه تضمین درستی همهٔ پاسخ‌ها و نقل‌قول‌ها و پچ‌های آینده نیست. اجرای محلی، سایت‌های دارای ورود، تشخیص عمومی همهٔ رازها و رفتار واقعی symlink در این حساب محدود ویندوز کامل تأیید نشده‌اند.

تست واقعی ادامهٔ خودکار هم با یک درخواست موفق شد: هر سه فایل پورتفولیو ایجاد شد، ارجاع CSS و JS با نام‌ها تطابق داشت، HTML دوباره خوانده شد و finish_work پایان را تأیید کرد. تست در پوشهٔ موقت است و پورتفولیوی کاربر را تغییر نمی‌دهد. دستور اجرای اختیاری scripts/smoke_test.py --live --portfolio است. این تست جریان کار و ارجاع فایل را تأیید می‌کند؛ اجرای مرورگر و JavaScript را تأیید نمی‌کند.

اگر پیام نبودن کتابخانه آمد، بررسی کنید نصب و اجرا با یک مفسر .venv باشند. pip install را با همان مسیر صریح تکرار کنید. اگر تنظیم محلی خطا داد، نام متغیر و URL و timeout را در ویرایشگر بررسی کنید و مقدار محرمانه را چاپ نکنید. خطای احراز هویت نیاز به بررسی یا جایگزینی کلید در حساب Ollama دارد؛ کلید را به گفتگو نفرستید.

اگر مدل در دسترس نبود یا API کد HTTP داد، مدل‌های مجاز حساب و OLLAMA_MODEL را بررسی کنید. سقف اعتبار یا نرخ را با منتظر ماندن برای اعتبار حساب یا مدل نصب‌شدهٔ محلی مدیریت کنید. خطای اتصال به اینترنت، VPN، اعتماد گواهی یا سرور محلی مرتبط است. کنترل گواهی TLS را برای رفع مشکل غیرفعال نکنید.

اگر پاسخ پس از یک عمل timeout شد، پیش از تکرار وضعیت واقعی را ببینید. اگر صفحه خوانده نشد، منبع اصلی دیگری امتحان کنید یا snippet را با احتیاط استفاده کنید؛ محتوای دریافت‌نشده را تأییدشده ننامید. اگر فایل مسدود شد، مسیر نسبی و متن کوچک UTF-8 و پسوند مجاز را بررسی کنید؛ انتقال راز به پسوند مجاز راه‌حل نیست.

برای دادهٔ خراب، همهٔ برنامه‌های ایجنت را ببندید و JSON فعال و .json.bak آن را در ویرایشگر باز کنید. فایل آسیب‌دیده را با نام محلی دیگر حفظ کنید، نسخهٔ پشتیبان معتبر را به نام فعال کپی و برنامه را دوباره اجرا کنید. فقط همان نوع دادهٔ خراب را بازیابی کنید تا دادهٔ دیگر تغییر نکند. اگر پس از قطع اجباری data/.lock باقی ماند، فقط بعد از اطمینان از بسته بودن همهٔ نمونه‌های ایجنت آن را بردارید. خروج عادی قفل را پاک می‌کند.

YES به بزرگی حروف حساس است. Enter یا جواب دیگر لغو می‌کند. دستور اسلش ناشناخته به مدل نمی‌رود و راهنما پیشنهاد می‌شود. شناسهٔ کار عدد صحیح مثبت است. فایلی که در زمان بررسی تغییر کرده باید دوباره خوانده و پیشنهاد تازه داده شود تا ویرایش فرد دیگر حفظ بماند.

## ۷. قابلیت‌ها، محدودیت‌ها و ادامهٔ کار

نسخهٔ اول گفتگو، حافظهٔ صریح، مدیریت کار، سرچ اطلاعات تازه، خواندن HTML عمومی، بررسی کد پروژه، تغییر فایل کوچک با تأیید، تاریخچهٔ موقت و دستور مستقیم محلی دارد. جدول docs/CAPABILITIES.md فرق پیاده‌سازی و شاهد تست را مشخص می‌کند.

اجرا نشده‌اند: فرمان دلخواه سیستم، تست خودکار کد، ورودی تصویر و صوت و PDF، کنترل مرورگر و ورود، کار زمان‌بندی‌شده، یادآوری، سرویس چندکاربره، رابط گرافیکی، جستجوی برداری و cloud نامحدود. این‌ها انتخاب آینده هستند و قابلیت پنهان فعلی نیستند. کاربر برای این نسخه روش ترمینالی را انتخاب کرده است.

فایل PROJECT_STATUS.md معماری، تصمیم محدوده، نتیجهٔ تست، محدودیت حریم خصوصی، ساختار گزارش و کار اختیاری آینده را ثبت می‌کند. همکار بعدی اول آن را بخواند و بعد چهار راهنمای اولیه را بررسی کند. گزارش دوزبانه و قابل فهم و با نام مالک پروژه باشد. پس از تغییر معنادار، نتیجهٔ تست و آموزش را به‌روز کنید؛ قابلیت را فقط از متن پرامپت نتیجه نگیرید.

قدم بعدی مناسب پس از استفادهٔ واقعی، جمع کردن چند نمونهٔ خطای واقعی با حذف راز و رفع کوچک‌ترین مشکل مشخص است. پچ فایل بزرگ یا رابط گرافیکی می‌تواند بعداً طراحی شود. قبل از آزمودن جریان فعلی در کار روزمره، چند چارچوب و لایهٔ اتوماسیون اضافه نکنید.

نام دقیق نویسنده و شش نشانی ارتباطی در تنظیم متمرکز گزارش قرار دارند. فونت دانلودی، تصویر بررسی، PDF و دادهٔ شخصی محلی و خارج از Git می‌مانند. منبع عمومی و آموزش و گزارش پیش از commit دستی قابل بررسی‌اند. در این کار commit یا push یا انتشار یا استقرار انجام نشده است.
